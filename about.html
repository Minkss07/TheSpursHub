What This Is

Spurs Hub is a personal side project combining live football data, a self-built score prediction model, and a fully custom front end. It's a Tottenham Hotspur fan site — built and maintained over time rather than as a one-off exercise.

How the Live Data Works

This site has no traditional backend — it's just static files. Calling a football data API directly from the browser has two problems: the API key would be publicly visible in the page source, and most free APIs block direct browser requests for security reasons (CORS).

To solve both at once, the site calls a small serverless function (a Cloudflare Worker) instead of the API directly. The Worker holds the real API key privately on Cloudflare's servers, forwards the request to football-data.org, and returns the data with the correct permissions for a browser to read it. The API key never appears anywhere in this site's public code.

The Prediction Model

Before each fixture, the site produces a probabilistic forecast using a Dixon-Coles style bivariate Poisson model — the standard approach in football analytics literature (Dixon & Coles, 1997). It is fully explainable rather than a black box.

Rather than guessing one scoreline, the model estimates expected goals for each side in that specific fixture, then derives the probability of every scoreline from 0-0 up to 8-8. The Dixon-Coles correction is applied because plain Poisson assumes the two teams' goals are independent, which measurably misprices low scores (0-0, 1-0, 0-1, 1-1).

Squad-Value-Informed Priors

The base model only sees historical scorelines, which means it's blind to squad rebuilds and managerial change — a team that spent heavily over the summer looks identical to one that didn't, until enough new-season matches accumulate. To partially address this, teams with thin match data are now shrunk toward a target informed by squad market value, rather than a flat league average.

This is a real, tested relationship: pre-season 2025/26 squad values were regressed against that season's actual final points across all 20 clubs — r = 0.669, R² = 44.8%. Squad value explains close to half the variance in final league position, which is a genuine signal.

One honest note on how this is scoped: the value regression is fit using a completed season's actual results, which means it can only be used safely for live, forward-looking predictions — using the finished 2025/26 season to inform 2026/27 has no lookahead problem at all. Using it inside the backtest or parameter sweep would be different: those replay past matches, and the regression would be peeking at outcomes it's being tested against. So it's deliberately, unconditionally disabled inside both — the Model Testing page's numbers reflect the model without this feature, exactly as originally validated. Data freshness is also uneven: Tottenham's value is summed directly from this site's own current squad data, while the other 19 clubs use last August's figures, since a clean current full-league dataset wasn't obtainable.

On Accuracy

Football match prediction has a hard ceiling. Professional bookmakers, with paid data feeds and full-time quantitative teams, land in the region of 50–60% on match outcomes. Any model claiming to be near-perfect is either overfitted to past data or misrepresenting itself.

The goal here is therefore not raw accuracy but calibration — when the model says 60%, that outcome should happen roughly 60% of the time. That is why the site reports a probability distribution rather than a single confident scoreline, and why it is tracked against my own predictions over the season.

Known limitations, stated plainly: the model sees only historical scorelines, so it cannot account for injuries, suspensions, squad turnover, fixture congestion, or managerial change. Tottenham's summer rebuild and change of manager are exactly the kind of thing it is blind to. Newly promoted teams have no top-flight history, so their ratings default toward the league average until data accumulates.

Reliability

Every live feature has a fallback: if the API is ever unavailable, rate-limited, or returns nothing useful, the site quietly falls back to curated static data instead of breaking. Nothing here depends entirely on a third party staying online.
